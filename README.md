# BhashaGuard AI

Multilingual, code-mixed phishing detection and prevention for regional-language users. Built for the Omnikon National Hackathon 2026 final round.

**"Any language. Any suspicious message. One intelligent security shield."**

## What this actually does

Paste a message, SMS, or URL — in English, Hindi, Tamil, Telugu, Bengali, or Kannada, in native script, romanized ("Hinglish"/"Tanglish"), or code-mixed with English — and get back:

- A **SAFE / SUSPICIOUS / HIGH RISK / PHISHING** verdict (0–100 risk score)
- A **Threat Breakdown**: social engineering, credential risk, impersonation, financial request, URL risk, content risk — each individually scored and explainable, not a single opaque number
- **Why it was flagged**, **what the attacker may want**, and **what you should do** — in plain language
- The **native-language explanation** and a separately-selectable **warning language** (detected language ≠ warning language, by design)
- An optional **spoken audio warning** (gTTS)

Same detection engine also powers a screenshot/OCR scanner, a QR code scanner, a browser extension prototype, detection history, a threat-insights dashboard, community scam reporting, and human-in-the-loop feedback.

## Quick start

```bash
cd backend
pip install -r requirements.txt

# Optional — get a free key at https://console.groq.com. Without it, the
# app still works fully via deterministic rule-based scoring.
export GROQ_API_KEY=your_key_here

uvicorn app:app --reload --port 8000
```

Open **http://localhost:8000** — the dashboard is served from the same origin as the API. Interactive API docs (auto-generated by FastAPI) are at **http://localhost:8000/docs**.

### Optional: OCR and QR scanning

```bash
pip install -r requirements-optional.txt
# + system Tesseract binary for OCR (not pip-installable):
#   Windows: https://github.com/UB-Mannheim/tesseract/wiki
#   Mac: brew install tesseract   |   Linux: apt install tesseract-ocr
```

Without these, `/api/scan/screenshot` and `/api/scan/qr` honestly report "not available" instead of failing silently or faking a result. Check `/api/health` to see what's active on a given deployment.

### Run the real evaluation

```bash
cd backend
python scripts/evaluate.py
```

Runs the detection pipeline against `data/demo_dataset.json` (38 labeled examples across 6 languages × native/romanized/code-mixed scripts) and writes measured accuracy/precision/recall/F1 to `data/eval_results.json` — the same numbers shown on the dashboard's Settings tab. Current run: **94.7% accuracy, 100% recall, 92.9% precision** on the rule-based engine alone (no LLM key needed for these numbers). Two known false positives are documented, not hidden — see the script output.

## Deploying (free tier, ~10 minutes)

**Render.com:**
1. Push this repo to GitHub (see below).
2. render.com → New → Web Service → connect your repo.
3. Root directory: `backend`. Build command: `pip install -r requirements.txt`. Start command: `uvicorn app:app --host 0.0.0.0 --port $PORT`.
4. Add environment variable `GROQ_API_KEY` (optional).
5. Deploy — you get one public URL serving both the dashboard and the API.

**Docker (alternative):**
```bash
docker build -t bhashaguard .
docker run -p 8000:8000 -e GROQ_API_KEY=your_key bhashaguard
```

**Pushing to GitHub:**
```bash
cd bhashaguard
git init && git add . && git commit -m "BhashaGuard AI"
git branch -M main
git remote add origin https://github.com/<your-username>/BhashaGuard-AI.git
git push -u origin main
```

## Project structure

```
backend/
  app.py                    # FastAPI app — composes routers, serves the dashboard
  routes/
    scan.py                  # /api/scan, /api/scan/screenshot, /api/scan/qr
    feedback.py               # /api/feedback (human-in-the-loop)
    report.py                 # /api/report, /api/reports (crowd-sourced reporting)
    history.py                 # /api/history, /api/insights, /api/eval
  services/
    pipeline.py                # the ONE shared analysis pipeline every route runs through
    language.py                 # native-script + romanized + code-mixed detection
    content_risk.py              # deterministic category/sub-score classifier + optional LLM refinement
    url_heuristics.py             # typosquat/TLD/shortener/IP/scam-wording checks
    fusion.py                      # noisy-OR fusion → 4-tier verdict + threat breakdown
    translation.py                  # category-aware safety guidance, per warning language
    ocr_service.py                   # screenshot text extraction (optional dependency)
    qr_service.py                     # QR decoding (optional dependency)
    voice.py                           # TTS generation
    storage.py                          # history/feedback/reports persistence
  scripts/evaluate.py           # real accuracy/precision/recall/F1 against data/demo_dataset.json
  data/demo_dataset.json         # 38 labeled examples, 6 languages × 3 script types
  requirements.txt                # core deps
  requirements-optional.txt        # OCR/QR extras
frontend/
  index.html                 # dashboard UI — Analyze / Screenshot / QR / History / Insights / Report / Settings
extension/
  manifest.json, background.js, content.js, popup.html/js   # Chrome Manifest V3 prototype
Dockerfile
```

## Architecture

```
Clients: Web Dashboard | Browser Extension | (WhatsApp Bot / SMS Guard — prototype, see below)
                              │
                              ▼
                    FastAPI Backend (routes/)
                              │
                              ▼
                  services/pipeline.py (shared)
        ┌─────────────┬──────────────┬─────────────┐
        ▼             ▼              ▼             ▼
  language.py   content_risk.py  url_heuristics.py  ocr/qr_service.py
   (script +      (deterministic    (typosquat,       (optional,
   code-mix ID)   category+sub-      TLD, shortener,   graceful
                  scores, +optional  scam wording)     degradation)
                  LLM refinement)
        └─────────────┴──────────────┴─────────────┘
                              ▼
                       fusion.py (noisy-OR,
                    threat breakdown, 4-tier verdict)
                              ▼
                translation.py (category-aware
              safety guidance, warning language)
                              ▼
                    voice.py (TTS) + storage.py
                     (history/feedback/reports)
```

**Design principle enforced throughout**: the LLM (Groq, optional) only ever refines the final risk score and writes the native-language explanation. Category classification, all four sub-signal scores, indicators, and attacker-goal inference are deterministic and rule-based, and run identically whether or not an LLM key is configured — this is what "risk-fusion architecture" means here, not a single model call wrapped in a UI.

## What's genuinely implemented vs. prototype vs. roadmap

**Fully implemented and tested end-to-end:**
- Multilingual detection: English, Hindi, Tamil, Telugu, Bengali, Kannada — native script, romanized, and code-mixed (all three modes, verified against the exact examples from the spec)
- Phishing category classification (12 categories) + 4 independent sub-signal scores
- Multi-signal risk fusion with full Threat Breakdown, 4-tier verdict (SAFE/SUSPICIOUS/HIGH RISK/PHISHING)
- URL intelligence: typosquat (token-based edit distance), suspicious TLDs, shorteners, raw IPs, scam wording in domains
- Explainable output: why-flagged indicators, attacker-goal inference, category-aware "what to do" guidance
- Warning language selection, independent of detected language, in 6 languages
- Voice-first warnings (gTTS)
- Screenshot OCR and QR decoding — genuinely functional when Tesseract/opencv are installed, honestly degrade when not
- Detection history, threat insights dashboard, feedback loop, crowd-sourced reporting with reputation thresholds — all backed by real stored data, not simulated
- Real measured model evaluation (accuracy/precision/recall/F1), not invented numbers

**Working prototype, clearly scoped:**
- **Browser extension** (`extension/`) — real Manifest V3 code, loadable unpacked in Chrome, calls the live backend and shows a warning banner for HIGH RISK/PHISHING pages. Needs a deployed backend URL configured via the popup.
- **WhatsApp Security Bot** — the backend API is bot-ready (`/api/scan` accepts any text, including what a WhatsApp webhook would forward), but no live Twilio/WhatsApp Business API webhook is wired up (that requires business account approval outside this timeline). The dashboard itself serves as the "forward a suspicious message" interface in the interim.
- **SMS Guard** — architecture note only: the realistic Android pattern is a share-target intent ("Share suspicious SMS to BhashaGuard") calling the same API, not background SMS interception (which needs restricted permissions). Not built as an Android app in this timeline.

**Explicitly not implemented (roadmap, not claimed):**
- Fine-tuned IndicBERT/XLM-RoBERTa model — the LLM-refinement + deterministic rule layer covers this scope for now; a trained classifier is the natural next step once more labeled data exists
- Supabase/PostgreSQL — storage currently uses local JSON files with the same function interface, so swapping the backend later is an implementation change, not a redesign
- Real threat-intelligence lookups (e.g. live PhishTank/VirusTotal API calls) — URL analysis is currently self-contained heuristics only

## Privacy

- Detection history stores only a ~80-character text snippet, never the full message
- Screenshots/QR images are processed in memory, never saved to disk
- API keys live server-side only — never sent to the frontend or the browser extension
- A single scam report is marked "unverified"; nothing is blocklisted from one report alone


## Screenshot OCR troubleshooting

The screenshot scanner uses Groq's current multimodal `qwen/qwen3.6-27b` model when `GROQ_API_KEY` is configured. The older `llama-3.2-11b-vision-preview` model is no longer supported. Screenshots larger than 3 MB are rejected before upload to avoid Groq's base64 image request limit. A local Tesseract fallback is used when available.

Optional environment variables:

```text
GROQ_API_KEY=your_key
GROQ_MODEL=qwen/qwen3.6-27b
GROQ_VISION_MODEL=qwen/qwen3.6-27b
```


## Deployment

### Render (recommended for the hackathon demo)
1. Push this repository to GitHub.
2. In Render, create a new **Web Service** from the GitHub repository.
3. Choose **Docker** and keep the repository root as the service root.
4. Add `GROQ_API_KEY` in the service Environment settings. Never commit the key to GitHub.
5. Set the health check path to `/api/health`.
6. Deploy and use the generated `onrender.com` URL as the prototype/deployment link.

The included `render.yaml` can also be used as a Render Blueprint.

### Google Cloud Run
The included Dockerfile listens on the platform-provided `PORT`, so the same repository can be deployed to Cloud Run with `gcloud run deploy --source .`.
